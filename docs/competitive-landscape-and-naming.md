# Competitive landscape and naming

**Date:** 2026-09-23  
**Status:** repository-level research complete; hands-on competitor tests and legal/registry clearance still pending.

Relevant public projects already cover parts of this problem: Relay (jcast90/relay), OpenGrove Handoff, Continuum, OpenAgentRelay, Qarinah, Handover and Keel. Therefore Relay Lab does not claim that handoff, local storage, Skills, audit logs, persistent state, proof gates or visual timelines are novel.

The falsifiable product hypothesis is narrower: make failure-aware, evidence-bound task continuation simple for a person switching reasoning/chat surfaces and local coding executors.

Same-fixture tests should compare:
- setup effort;
- handoff time;
- clarification count;
- lost/contradicted constraints;
- safe-stop behavior for stale or missing evidence;
- interruption/restart recovery;
- human intervention count;
- final task completion.

## Naming

- **TaskContinuum:** rejected; exact active public project exists.
- **AgentContinuum:** hold; no exact GitHub match found in the earlier search, but broad semantics and legal clearance remain unresolved.
- **Continuark:** research candidate only.
- **CarryLedger:** research candidate only.
- **TaskKeel:** deprioritized due adjacent Keel products.

GitHub name availability is not trademark clearance. Final brand requires package registry, domain, app/store/social and relevant trademark similarity checks.

Current public repository slug: `relay-continuity-lab`. It is intentionally an engineering name and may remain stable even if the product brand changes.
